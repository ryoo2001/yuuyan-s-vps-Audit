# 存储说明

中心所有数据库采用同一套表结构（内部版本号 schema v2）。每个地区使用一个独立的数据库。同一数据库中存在多个采集点时，各采集点拥有独立前缀的数据表、独立的上传身份、批次编号（epoch）和序号。

## 表结构

每个采集点拥有一套独立的数据表：

- 原始数据表和上传进度表；
- `traffic_monthly` 月累计表，由六个触发器在原始数据新增、修改、删除时自动更新；
- 常用查询所需的索引。

每个数据库另有三张公共表：`audit_schema` 记录表结构版本，`traffic_calendar` 保存已归档部分的月累计，`archive_receipts` 记录每次归档的内容。

查询统一通过五个中文视图进行。汇总多个采集点时，视图会为每条记录附加采集点名称后再合并。由于各采集点的表独立编号，可能出现相同 ID，因此不能直接用 ID 跨表关联。

## 数据分层

| 分层 | 默认范围 | 读取方式 |
|---|---|---|
| 热数据 | 最近 7 天，可调整为 3–7 天 | 五个中文视图默认查询此范围 |
| 温数据 | 热数据之前、14 天之内 | 查询时指定时间范围，或直接查询原始表 |
| 冷数据 | 14 天之前 | 存放于数据库外的月度归档文件，仅在明确需要时读取 |

热数据与温数据存放在同一张表中，仅按时间区分，不重复存储。

归档时，先生成压缩文件并确认已写入磁盘，再核对内容、行数和校验和。核对通过后，在同一事务中更新月累计、写入归档记录并删除库内对应数据。任一步骤失败，库内数据均保持不变。数据库设有删除保护机制，未经归档记录的数据无法删除，不得绕过该机制。

归档文件按北京时间月份存放。归档文件及其配套记录属于正式数据，并非临时备份，不得作为冗余文件清理。月累计等于库内现有数据与当月已归档部分累计之和，计算时无需读取归档文件。

## 新增地区

使用 `central/region.py` 创建数据库，该脚本会建立统一的表结构和分层规则。创建前须确定数据库名称、采集点表前缀、上传身份和账号权限；创建后须分别验证上传、只读查询和归档功能。不得复制某个现有地区专用的 SQL，也不得重复执行历史建库脚本。

连接真实 MySQL 的测试位于 `central/test_storage_mysql.py`、`central/test_archive_mysql.py`、`central/test_monthbook_mysql.py`，仅可在专用测试库中运行。操作注意事项见 [运维说明](operations.md)。
