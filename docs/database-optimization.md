# 数据库优化

数据库优化主要从三方面入手：缩小查询范围、在写入时同步更新汇总、将旧数据迁出数据库。原始数据、上传身份及五个中文视图的列定义均保持不变。

| 目标 | 方法 | 代码 |
|---|---|---|
| 避免全表扫描 | 先按采集点分别汇总，再合并汇总结果 | `central/hk_summary.py` |
| 加快近期明细查询 | 按时间及常用条件建立索引，默认仅查询最近 7 天 | `central/detail_view.py`、`central/storage.py` |
| 月累计无需实时计算 | 写入时由触发器更新月累计表，归档时保留累计值 | `central/monthbook.py` |
| 降低上传开销 | 分批写入、限制队列长度、复用数据库连接 | `central/publish.py`、`central/edge_queue.py` |
| 控制数据库规模 | 校验无误后归档并写入归档记录，未经记录的数据无法删除 | `central/tiering.py`、`central/archive.py` |

对比优化前后效果时，应选取同一截止时间，比较行数及上传、下载字节数，并逐个采集点核对月累计。评估查询耗时应区分数据库执行时间与客户端下载时间。历史测量结果不代表当前性能。

调整索引、表空间或数据库内存前，均须先在现场测量并单独审查，不得直接重新执行 `deploy/` 中的迁移脚本。表结构约定见 [存储说明](storage.md)，发布步骤见 [运维说明](operations.md)。
