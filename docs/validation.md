# 分级校验

应根据改动内容运行对应的检查，无需每次执行全部检查。本地检查通过仅表明代码和文档符合约定，不代表线上运行正常。

| 改动类型 | `--business` 取值 | 检查内容 |
|---|---|---|
| 文档 | `docs` | 链接有效性，配置及视图列名与文档的一致性 |
| 采集或指纹匹配 | `collector` | 抓包、传输及运行时测试 |
| 本地查询脚本 | `query` | 参数、输出列及只读限制 |
| 视图或单位 | `views` | MySQL 视图、SQLite 视图、5 秒去重及速率 |
| 上传 | `sync` | 重复写入的正确性，epoch、序号及确认位置 |
| 保留或归档 | `retention` | 失败回滚、字节数守恒、先归档后删除 |
| 权限 | `access` | 允许的操作可正常执行，写入数据、修改表结构、读取系统表均被拒绝 |
| 发布工具 | `deploy` | 发布包的生成与校验规则 |
| 全部 | `full` | 全部离线测试 |

```powershell
python tools/check.py
python tools/validate.py --business docs --run
python tools/validate.py --business collector --changed audit.py --run
python tools/validate.py --business views --changed central/views.sql --run
```

`--changed` 可多次指定。不加 `--run` 时仅输出检查计划；加上 `--run` 后也只执行本地检查，不连接服务器。输出中的 L0–L3 表示改动的风险等级；即使为 L3，也不会自动运行全部检查。

## 新装机器

使用已验收的版本安装新入口机时选用 `edge-install`，安装新落地机时选用 `terminal-install`。二者均要求本地具备对应角色、对应文件版本的验收记录（私有文件，不纳入仓库）。若缺少记录或文件已被修改，须补充运行相关测试，不能以历史结果代替。

## 上线后的现场确认

- 至少经过一个完整的 5 秒窗口；
- 至少完成一轮上传，且确认位置有所前进；
- 已使用真实的只读账号完成查询；
- 选取固定的截止时间，采集端与中心库的数值一致。

若无流量、无法识别客户端 IP 或确认位置未前进，应如实记为"未验证"，不应通过清除数据使检查通过。连接真实 MySQL 的测试仅可在专用测试库中运行。

## 公开仓库中的检查

公开仓库不包含生产日志和验收记录。`tools/check.py` 在公开仓库中检查源码、配置和文档；本地存在私有基线文件时，还会检查其一致性。只有加上 `--baseline` 参数，才会将源码与已验收版本的哈希进行比对；缺少基线文件时将直接报错。
